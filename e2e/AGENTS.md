# E2E testing guidelines and best practices for Playwright tests

## Running

`make test-e2e` rebuilds the embedded frontend, builds the server with the `e2e` build tag, cleans `data-e2e/`,
starts it, and runs every spec in parallel; it is the only e2e gate. Rebuilding first is why a committed
`backend/frontend/dist` snapshot never serves superseded browser code here. The tag raises every rate limit
10000x, because the suite registers a fresh account per test and would otherwise exhaust the production auth
tier. Tests have zero retries, so they must be deterministic. Iterate on one test with
`pnpm exec playwright test e2e/file.spec.ts:LINE`, and add `--trace on` to record a trace. Use
`make test-e2e PLAYWRIGHT_ARGS=--ui` for interactive UI mode.

The `e2e` build tag also swaps the OAuth providers for fakes that log in deterministic accounts and raises the
server user quota so every spec can register its own user. A binary built without the tag has none of it, so
`make build` and `make test` keep production behavior.

## Helpers

Import `test`, `expect`, and helpers from `./helpers`:

- `registerUser(request, prefix)` creates an isolated user and returns `{ email, token }`. Every test registers
  its own user through it; it retries on 429.
- `createClient(request, token)` returns the typed SDK client. Use it for all API calls instead of raw
  `request.get` or `request.post`, so tests share the backend's generated contracts.
- `gotoWithSession(page, token, path?)` installs a normal API-issued credential as an HttpOnly Secure
  host cookie for unrelated UI setup. Authentication tests must exercise the actual browser login routes.
- `waitForWorkspace(page)` waits for the usable workspace tree and returns its ID.
- `switchToMarkdownMode`, `getEditorContent`, and `fillEditorContent` drive the editor.
- `test.screenshot(title, fn)` tags a test `@screenshot`; the `takeScreenshot` fixture captures images.

## App Behavior

- Open the app with `gotoWithSession(page, token)`, then call `waitForWorkspace(page)` before workspace interactions.
- Autosave runs 2 s after the last edit, or at once when the user opens another node. Poll the API with
  `expect(...).toPass()` to observe the save.
- Sidebar nodes carry `data-testid="sidebar-node-<id>"`. Their `delete-node-button` appears on hover.
- Timeouts: 15 s for the first sidebar load, 10 s for URL changes, 5 s for other elements and polling.
