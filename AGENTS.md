# mddb

mddb is a Notion-like document and database system: a Go backend with an embedded SolidJS frontend, storing
data as Markdown, JSONL, and assets in git repositories. Read [backend/AGENTS.md](backend/AGENTS.md),
[frontend/AGENTS.md](frontend/AGENTS.md), or [e2e/AGENTS.md](e2e/AGENTS.md) before editing those trees.

## Workflow

- Run `make git-hooks` before the first change.
- After a change, run `make fix`, then `make verify`, the read-only pre-push gate. `make test` runs Go and
  frontend unit tests; `make coverage` reports their coverage.
- After a UI or API change, also run `make test-e2e`. The server log is at `data-e2e/server.log`.
- After a visible UI change, run `make screenshots-update` and commit the documentation captures.
- `make` lists the common targets and their cost.
- `.editorconfig` sets indentation and width. Ruff repeats the width in `pyproject.toml` because it does not
  read `.editorconfig`.
- The first-line comment of each file feeds the file index below; update it when the file's purpose changes.
- Plans are `docs/PLAN_*.md` files in the owning module.
- User and integration guides live at docs.mddb.app (the `docs.mddb.app` repository). Keep durable contracts in
  comments beside the owning source, not in Markdown.

## Versioned Contracts

Every wire API and serialized format has a version. Wire APIs are HTTP routes, SSE events, MCP tools, resources
and cursors, and SDK types. Serialized formats are the workspace files, JSONL tables, configuration, caches,
cookies, and browser storage that mddb writes. A route path, file path, or `version` field holds the version; a
format without one is version 1.

A breaking change ships as version N+1 beside version N:

- Breaking: remove or rename a field, route, or enum value; change a type, unit, or meaning; make an optional
  field required; reject input that version N accepts. Adding an optional field or a route, or changing a
  default, is not breaking.
- Copy the vN package to vN+1 and change the copy. API DTOs live in `backend/internal/server/dto/vN`; persisted
  schemas live in `data/vN` beneath their owner, such as `backend/internal/storage/identity/data/v1`.
- Use the vN types directly. Do not declare type, constant, or variable aliases or forwarding wrappers for them;
  saving churn does not justify an alias.
- Move clients and writers to vN+1. Serve and read vN through an adapter over the current implementation.
- Mark each vN declaration and adapter with
  `TODO(YYYY-MM-DD): delete vN once this date has passed and two release tags contain vN+1.` The date is the commit
  date plus 7 days. Count tags with `git fetch --tags origin && git tag --contains <commit that added vN+1>`.
- When both conditions hold, delete vN with its adapter, tests, and generated SDK.

## Roll Go Mode

Pick a Git commit and roll both the `github.com/gomodedev/gomode` Go module and the `@gomodedev/gomode` package in
`package.json` to it. Run `make test-e2e SPEC=e2e/voice-context-health.spec.ts` to rebuild the embedded frontend and
check browser and native voice recovery. Commit the updated `backend/frontend/dist`.

## Python tools

Run Python tools and repository scripts with `uv run --locked`.
Run `uv lock` after changing Python dependencies.
